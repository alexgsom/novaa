# Nova Native 0.9: тестування графічних Windows-програм

Це **експериментальна реалізація**. Новий `novac.nova` компілює графічний код у `.nbc`, а Win32 UI тепер викликається безпосередньо із C++ байткодної VM. Python не використовується для виконання програми, а компілятор C++ не потрібен для збирання кожного нового `.exe`, якщо встановлені готові `nova-native.exe` і `nova-windowed.exe`.

## Швидкий старт на Windows 10/11 x64

Потрібні дві **справжні Windows** програми: `bin/nova-native.exe` та `bin/nova-windowed.exe`. Отримайте їх після успішної Windows CI-збірки або один раз виконайте `./build_windows.ps1 -Compiler MSVC` у Developer PowerShell.

```powershell
./nova.ps1 doctor
./nova.ps1 build -Source examples/windows09/hello_gui.nova -Output bin/NovaHello09.exe -Windowed
./bin/NovaHello09.exe
```

Повторіть для `counter_gui.nova` і `notes_gui.nova`. Для CLI-діагностики збирайте **без** `-Windowed`, щоб помилки з'являлися в консолі.

## Як працюють callback

```nova
import ui
let app = ui.window("Nova", 450, 280)
let caption = ui.label(app, "0")
let state = {"count": 0}
function increment()
    state.count = state.count + 1
    caption.set(str(state.count))
end
ui.button(app, "+1", increment)
ui.run(app)
```

- Функція-обробник **має бути оголошеною і не приймати параметрів**.
- Можна передати функцію (`increment`) або її ім'я як рядок (`"increment"`).
- Кнопка або меню викликає ту саму байткодну VM; вона бачить глобальні змінні та спільні об'єкти.
- Присвоєння звичайної змінної всередині функції створює локальну змінну. Для змінного стану між подіями використовуйте спільний об'єкт (`state.count`).
- `.get()`/`.set(...)` доступні для змінних, що зберігають UI-контрол; також працюють `ui.get(control)`/`ui.set(control, value)`.
- `ui.run(app)` обробляє Win32-події; програма завершується після закриття вікна.

## Рекомендована ручна перевірка перед релізом

1. `hello_gui`: ввести українське або польське ім'я, натиснути кнопку, переконатися, що напис змінився.
2. `counter_gui`: тричі натиснути `+1`, потім Reset, переконатися, що напис показує 3, потім 0.
3. `notes_gui`: зберегти багаторядкову нотатку з кирилицею; перезапустити програму і завантажити нотатку.
4. Закрити вікно кнопкою X, перевірити завершення процесу.
5. Перевірити перевищення обмеження кроків у callback, повідомлення про помилку та коректне закриття вікна.
6. Перевірити `.exe` без встановленого Python і Visual Studio; відкрити його на іншій Windows 10/11 x64.

Автоматизований Win32 smoke `examples/windows09/ui_smoke.nova` **не натискає кнопок**: створює вікно та контролі, перевіряє їхній текст і завершення. Графічні callback обов'язково перевірити вручну на Windows. На Linux GUI не відкриється: там перевірено компіляцію байткоду, пакування, самокомпіляцію і повідомлення про недоступність Win32.

## Межі та безпека

- Це не повний еквівалент усіх можливостей Nova 1.2: `try/catch`, `match`, користувацькі `.nova`-імпорти в байткоді та замикання залишаються обмеженнями.
- Немає sandbox: програма виконується з правами користувача.
- Контрольна сума FNV-1a у запакованому виконуваному файлі — **не криптографічний підпис**.
- `ui` підтримується лише у Win32-системах, тестів реальної Windows збірки у цьому Linux-середовищі ще немає.
