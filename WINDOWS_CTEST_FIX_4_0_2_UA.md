# Nova Studio 4.0.2 — Hyper40 Windows CTest Diagnostics & CI Stabilization

Дата: 24.11.2026

## Що показав надісланий лог

- MSVC/CMake на Windows успішно зібрали `nova-native.exe`, `nova-windowed.exe` та `NovaStudio.exe`.
- 9 із 10 тестів CTest пройшли успішно.
- `nova-studio-hyper40-tests` аварійно завершився з `0xc0000409` (Windows fast-fail/STATUS_STACK_BUFFER_OVERRUN). Цей код **сам по собі не встановлює причину**: це може бути відмова CRT/`assert`, некоректний параметр або проблема пам'яті.
- У журналі немає імені перевірки, яка спричинила завершення, тому підтвердити конкретний дефект у Hyper40 з одного логу неможливо.

## Що змінено

Змінено лише `tests/studio_hyper40_native.cpp`:

1. Усі `assert(...)` замінені на явні `CHECK(...)`, які виконуються однаково в Debug та Release й повідомляють **файл, рядок та умову**.
2. Тест розбитий на розділи `Command Center`, `Project X-Ray`, `Time Machine`, `Nova Forge` із діагностикою у stdout/stderr.
3. Перевірки `optional` та індексування виконуються послідовно, без небезпечного розіменування перед перевіркою.
4. Тимчасова тестова директорія тепер має унікальну назву, щоб виключити колізії між запусками CI.
5. Повідомляються причини проблем із файловою системою та код винятку, коли це можливо; тест прибирає свої тимчасові файли.

Код продукту Nova Studio 4.0.1 **не змінювався**. Це стабілізація тесту і діагностика, а не безпідставна заява, що невизначена Windows-помилка вже остаточно виправлена.

## Перевірки в цьому середовищі

- Linux, C++17 Release: 10/10 CTest успішні.
- Тест Hyper40 під Clang AddressSanitizer + UndefinedBehaviorSanitizer успішний.
- MSVC/Windows у цьому середовищі недоступні. Windows-прохідність очікує наступного CI запуску.

## Встановлення

**Рекомендовано:** розпакуйте `Nova_Studio_4_0_2_Hyper40_CI_Full_Source.zip` поверх репозиторію, зберігаючи структуру папок, закомітьте та запуште зміни.

**Альтернатива:** розпакуйте `Nova_Studio_4_0_2_Hyper40_CI_Patch.zip` у корінь репозиторію Nova Studio 4.0.1 із перезаписом однойменних файлів. Самого ZIP у репозиторій додавати не потрібно.

У GitHub Actions запустіть **Nova Windows x64 Acceptance**. Якщо Hyper40 знову не пройде, CTest тепер повинен показати `[HYPER40 FAILED]` із конкретною умовою або останній успішно розпочатий блок `[HYPER40]`.

Надішліть повний текст з цього блоку (`[HYPER40] ...`, `[HYPER40 FAILED] ...`) — це дозволить відремонтувати відповідну функцію замість приховування помилки тесту.

Після проходження **усіх** кроків Windows workflow у розділі `Artifacts` має з'явитися архів `nova-windows-x64`.
