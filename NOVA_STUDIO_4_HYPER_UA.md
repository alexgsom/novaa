# Nova Studio 4.0 Hyper — великий функціональний апдейт (Preview)

**Основа:** Nova Studio 3.0, Update 20–24. Підтримка `.nova`, self-hosted компілятора, C++ VM, Nova GUI, три мовні варіанти (українська, польська, англійська), AI Proof, App Designer, вкладки та базове трасування VM збережена.

**Стиль:** темний графітовий мінімалізм, без кіберпанку. У верхній панелі з'явилися Nova Forge, X-Ray, Quality Gate і Command Center. Адаптивні бокові панелі з Update 20 збережено. Частина інтерфейсу досі використовує стандартні елементи Windows; власної кросплатформної UI-системи немає.

## П'ять великих можливостей

### 1. Command Center / `Ctrl+Shift+P`

Інтерактивна темна палітра замість старого меню Quick actions. Вводь назву дії, `.nova`-файла або функції з відкритого коду — результат фільтрується на льоту. Пошук fuzzy: допускає пропуски символів і пропуск роздільників. Стрілки ↑/↓, Enter, Escape, подвійний клік. Кнопка `⌕ Command Center` завжди доступна у верхній панелі, коли вистачає місця. Палітра працює офлайн.

### 2. Nova Forge / `File → Nova Forge`

Створення **повноцінного локального стартового проєкту** з одного з трьох шаблонів:

- **Counter** — графічна Windows-програма: кнопки, callback, спільний стан.
- **Notes** — графічний нотатник із локальним збереженням даних.
- **Tasks** — консольний менеджер справ із JSON-сховищем.

Обери шаблон та **існуючу порожню папку**. Forge створить `main.nova` і `README.md`, відкриє програму. Стандартні файли не перезаписуються. Шаблони перевірені реальним нативним компілятором Nova на Linux. Графічні шаблони запускаються лише на Windows із зібраними Nova Win32 runtime.

### 3. Project X-Ray / `Nova → Project X-Ray`

Локальний огляд усіх придатних `.nova`-файлів у папці проєкту: кількість файлів, рядків, функцій, імпортів, `TODO/FIXME`, дубльовані оголошення функцій та не знайдені локальні модулі. Результат — у нижній панелі з окремим списком знахідок; **подвійний клік відкриває відповідний файл і рядок**. Жодного ШІ, мережі чи виконання коду. Обмеження: до 250 файлів, 256 KiB на файл, 4 MiB усього. Аналізує збережені версії з диска, є статичною евристикою (не повноцінним LSP та не безпековим аудитом).

### 4. Project Quality Gate / `Nova → Project Quality Gate`

Одна дія запускає **серійну компіляцію до 100 `.nova`-файлів** проєкту нативним self-hosted компілятором. Кожен файл обмежено 256 KiB. Результат: PASS/FAIL по кожному файлу, лічильник та обмежені повідомлення про помилки. Жодна програма не запускається: створений байткод видаляється. Перевірка йде в окремому потоці, Stop скасовує поточний процес і подальші перевірки. **Це не тести логіки й не доказ коректності взаємодії всіх модулів.** Зміни в несхоронених вкладках можуть не враховуватися.

### 5. Time Machine / `File → Time Machine`

Явні локальні контрольні точки коду без Git і хмарних сервісів. Команда `Create checkpoint` зберігає вміст редактора у `.nova-history/` проєкту (максимум 12 версій на файл). `Restore checkpoint` спочатку зберігає поточний буфер як захисну точку, а тоді завантажує вибрану версію **в редактор без перезапису `.nova` на диску**; потрібно підтвердження й окремий Save. Перевіряє, чи файл є всередині проєкту; не дозволяє запис у сторонній шлях. `.nova-history/` виключено з Explorer і пошуку. Для нового Git-репозиторію рекомендуємо додати `.nova-history/` у `.gitignore` (у репозиторії Nova запис уже є).

## Виправлення, що впливає на надійність

У попередньому Update 24 захист `--trace-steps` помилково потрапив до `NOVA_EMBEDDED_APP`, де `traceSteps` і `mode` відсутні. Це порушувало збірку standalone Nova-застосунків. Видалено хибну перевірку лише з цієї гілки; захист у звичайному CLI збережено. Після виправлення окремий standalone застосунок успішно зібраний і запущений.

## Перевірки (Linux, 2026-11-24)

- Складання CMake: успішно для доступних Linux-цілей.
- CTest: **10 із 10 PASS**, включно з новими тестами fuzzy-пошуку, X-Ray, Forge, Time Machine і захисту від перезапису.
- Studio Python regressions: **46 OK** (4 SKIP при початковій перевірці; на повторній перевірці всі 46 завершилися OK залежно від оточення).
- `sh nova.sh doctor`: **PASS** — компілятор, VM, запуск і пакування.
- Генеровані джерела трьох шаблонів Forge скомпілювалися у байткод.
- Standalone Nova застосунок зібрався з вихідного файлу та запустився.
- Трасування `--trace-steps 4` підтверджено на `.nbc`.

**Ще не перевірено:** реальний збір Windows/MSVC, Win32 GUI smoke, візуальний стан Command Center, click-flow Forge/X-Ray/Time Machine/Quality Gate в Windows. Windows CI workflow розширено, щоб зібрати і запустити новий набір portable C++ тестів. **З архіву не можна одразу запустити готовий Windows `.exe`** — це вихідний код.

## Як встановити оновлення

1. Збережи попередній проєкт у Git / резервній копії.
2. Якщо у тебе Update 20–24 Progress, розпакуй **Hyper Patch** у корінь проєкту зі збереженням структури `studio/`, `src/`, `tests/`, `.github/` та заміною змінених файлів. Інакше розпакуй **Hyper Full** у порожню папку.
3. У GitHub Desktop зроби Commit і Push до свого репозиторію.
4. У GitHub → **Actions → Nova Windows x64 Acceptance** запусти перевірку або відкрий автоматичний запуск. Якщо все зелене, завантаж `nova-windows-x64` з Artifacts. На Windows також можна зібрати власноруч: `./build_windows.ps1 -Compiler MSVC` у Developer PowerShell.
5. Після отримання Windows-збірки запусти `bin/NovaStudio.exe`. Перевір палітру `Ctrl+Shift+P`, Forge, X-Ray, Quality Gate, Time Machine та старі Run/F5, Compile/F6, Build/F7.

## Межі випуску

Це **Nova Studio 4.0 Hyper Preview**, а не підтверджений стабільний продукт. Не заявлено повноцінного інтерактивного дебагера з breakpoints, повного LSP, автоматичної AI-агентності або автооновлення Windows-клієнта. ШІ, як раніше, працює тільки за явним запитом/згодою на передачу даних і з переглядом змін перед застосуванням.
