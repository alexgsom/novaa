# Self-hosted Nova: досягнення та наступні рубежі — 0.9

## Що вже вміємо

1. **Nova-authored compiler** — `compiler/novac.nova` написаний мовою Nova, генерує `.nbc` і може компілювати власний текст. `stage1.nbc == stage2.nbc` побайтово.
2. **Нативна VM без Python** — наш C++17 runtime виконує байткод, включно з функціями, рекурсією, циклами, списками, об'єктами і модулями стандартної бібліотеки.
3. **Пакувальник без повторної C++-компіляції** — готовий native runtime + байткод + footer -> один виконуваний файл. На Linux це перевірено; для Windows потрібен попередньо зібраний PE x64 runner.
4. **Графічний Win32 байткод, 0.9** — компілятор генерує код для `ui`, а C++ VM обробляє методи UI і callback кнопок/меню. На Linux підтверджені компіляція та регресійні тести; справжні події Windows очікують перевірки.

## Що залишилося, щоб вийти в стабільний Windows-реліз

- Запустити MSVC Windows CI; протестувати всі чотири Win32-програми на Windows 10/11, включно з ручним натисканням кнопок і роботою з Unicode.
- Надати підписані й перевірені Windows release binaries `nova-native.exe`, `nova-windowed.exe`, `novac_selfhost.nbc`, інсталятор та контрольні SHA256.
- Забезпечити діагностику з номером вихідного рядка, обмеження файлів/часу, захист від некоректного байткоду і регресії в GUI event loop.
- Додати відсутню частину синтаксису (`try/catch`, `match`, імпорт власних модулів), пакування ресурсів та стабільну бібліотеку компонентів.
- Підтримати AOT / власний native backend пізніше, якщо потрібна повна незалежність від C++ runtime. Це значно більший проєкт і **не є умовою вже досягнутої самокомпіляції компілятора**.

## Важливі відмінності

- **Самокомпіляція Nova-компілятора до байткоду досягнута.**
- **Незалежність запуску та компіляції Nova-коду від Python досягнута для підтримуваної підмножини.**
- **Власний Windows машинний компілятор чи self-hosted VM ще НЕ реалізовані.** C++ потрібен для початкового збирання Windows-рушія.
- **Виконання GUI на Windows ще НЕ перевірене тут.** Це окремий релізний бар'єр.
